# fin14 — Product Requirements Document

**Version:** 0.13.0  
**Status:** Draft  
**Date:** 2026-06-08  

---

## 1. Overview

Version 0.13.0 builds on the 0.12.0 contract and addresses one concrete adoption
problem: **JavaScript-framework output** (Next.js, Nuxt, SvelteKit, and any
hydration framework that ships a large shared client bundle on first load).

A default Next.js static export ships ~190 kB of JavaScript across shared chunks
under `_next/static/chunks/*.js`. fin14 0.12.0 reported every page as failing, with
the same six or seven chunks repeated per page, each carrying the generic advice
"JS looks large; consider splitting or deferring" — advice that is wrong for chunks
that are already split and already deferred. The verdict (over budget) was correct;
the **diagnosis** was noisy and misleading.

0.13.0 keeps the verdict honest and improves the diagnosis, and adds an explicit,
honest **opt-in** to exclude shared client JS from the budget. Everything else
preserves the 0.12.0 contract.

These changes stay inside the product's principles:

- **fin14 still measures, never transforms** (D4). The default budget number is
  unchanged: those bytes really ship on first visit, so by default they are counted.
- **The opt-in never lies** (D48 precedent). Excluded bytes are always shown
  (`195.8 kB ignored via …`), never silently dropped, and the opt-in is the user's
  explicit choice — like `warnings.exclude`.
- **The measurement core is untouched.** `collector.js`, `measurer.js`, and
  `validator.js` are unchanged in contract; ignoring is a pure transform applied
  *after* measurement (`@fin14/core/ignore.js`).

## 2. Design Decisions (recorded)

Continues the table from 0.12.0 (last entry D64).

| # | Decision | Choice | Reason |
|---|---------|---------|--------|
| D65 | Asset-level ignore | `budget.ignore` — glob list matched against each resource's `displayPath`; matching resources are excluded from the page total but reported as `ignoredBytes` / `ignoredResources` | `project.exclude` filters *pages*, not assets; users need to drop framework runtime assets from the budget without abandoning the linter. Showing the ignored total keeps it honest |
| D66 | Ignore presets | `budget.ignore_presets` — named presets expanding to globs; `nextjs` → `_next/static/chunks/**.js` | One-line opt-in for the common case; preset is scoped to JS (`.js`) so the framework CSS chunk is still honestly counted, matching the "client JS" label |
| D67 | Ignore as post-measurement transform | A page/summary is measured normally, then `applyIgnoreToSummary` recomputes totals, status, E13/E14, and cut candidates over the *counted* set | Keeps the measurement core honest and untouched; the same pure transform powers the static CLI and the dev live toggle, so there is one source of truth |
| D68 | Dev live preset toggle | Session-only toggle of `ignore_presets`; TUI auto-detect band (`⚡ Next.js detected — press F …`) + an "ignore presets" section on the `F` screen; web report **Filter Config Panel** (renamed from "Warning Filters") with a checkbox; TUI↔web synced via SSE; no write-back to disk | Mirrors the warning-filters pattern (D48/D49/D52); discoverable for `npx fin14 dev` users; the recompute reuses already-measured resource bytes (no disk re-read) |
| D69 | De-noised cut candidates + context advice | Per page, cut candidates are display-capped (top 3) with a roll-up line (`… +N more chunks (X kB)`); the JS hint switches to "large client JS bundle; ship less JS or static-render" once a page has ≥ 3 JS chunks (already split) | The repeated per-chunk dump and the misleading "split or defer" advice were the core noise; display-only, the `cutCandidates` data is unchanged (consistent with D53) |
| D70 | Systemic shared-JS hint + framework naming | When pages fail and large JS is shared across pages, one site-level hint is emitted; it names the framework (`Next.js detected`) when `_next/` assets are present and points at the opt-in | One honest, actionable line at the right altitude instead of per-chunk repetition; naming is display-layer only (like D9 output-dir detection) and never changes the measured bytes |
| D71 | JSON ignore fields | `--json` per-page results gain `ignoredBytes` (number) and `ignoredResources` (array, same shape as `resources`); `schemaVersion` stays `1` (additive, backward compatible) | CI/tooling can see what was excluded and why without parsing the human report |

## 3. Configuration additions (`fin14.toml`)

```toml
[budget]
ignore         = []          # asset globs excluded from the budget (optional)
ignore_presets = []          # named presets, e.g. ["nextjs"] (optional)
```

- `budget.ignore` — array of globs (same matcher as `project.include`/`exclude`,
  D56), matched against each resource's `displayPath` (path relative to the output
  dir; full URL hostname+path for externals). Matching resources are removed from the
  page total and surfaced as `ignoredBytes` / `ignoredResources`.
- `budget.ignore_presets` — array of preset names. Unknown names are a config error
  (exit code 2, D57). Currently defined: `nextjs` → `_next/static/chunks/**.js`.
- The effective ignore set is `budget.ignore` ∪ (globs of each active preset).
- Ignored externals are not counted and do not raise E14; E13 is recomputed on the
  counted total. Per-page budgets/overrides (D55) still apply to the counted total.

The honest-measurement principle is preserved: ignoring is opt-in and always visible.

## 4. CLI behavior

**Default command & `audit`.** After measuring, the summary is passed through the
ignore transform. Each flagged page shows an `(N kB ignored via <source>)` line when
anything was ignored (`<source>` is the preset name(s) or `budget.ignore`). Cut
candidates are display-capped with a roll-up; the JS advice is context-aware (D69).
A single systemic hint (D70) is printed after the page list when applicable.

Exit codes are unchanged (D57): a page over its *counted* budget still fails with
exit 1; opting in to a preset that brings every page under budget yields exit 0.

**`--json`.** Per-page results carry `ignoredBytes` and `ignoredResources` (D71).
`resources`, `totalBytes`, `cutCandidates`, and `status` reflect the counted set.

---

## 5. Dev mode behavior

`fin14 dev` initializes the active preset set from `budget.ignore_presets`. The
measured (raw) summary is kept; the rendered/broadcast summary is the ignore-applied
view, recomputed whenever a preset is toggled (no re-measurement).

- **TUI.** On the pages screen, when `_next/` assets are detected and the preset is
  inactive, a band reads `⚡ Next.js detected — press F to ignore N kB shared JS`.
  The `F` screen gains an "ignore presets" section above "warning filters"; the
  cursor spans both; `Space` toggles. Header counters update live.
- **Web report.** The warning-config panel is renamed **Filter Config Panel** and
  gains an "ignore presets" subsection (one checkbox per preset) that `POST`s to
  `/ignore/toggle`. The page-detail panel shows an "N ignored via active preset"
  note.
- **Sync.** Toggling on either surface updates `state.activePresets` and broadcasts
  an updated summary via SSE (carrying `activePresets` and `availablePresets`), so
  TUI and web stay consistent. Session-only; resets to the config values on restart.

---

## 6. Out of scope (unchanged)

No CSS purge or any transformation (D4/D15); no per-framework measurement adapters
(the preset is a display/budget opt-in, not framework code in the measurement path);
no persistent write-back of dev toggles; no JavaScript import graph.
